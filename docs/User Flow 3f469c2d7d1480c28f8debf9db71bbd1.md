# User Flow

1. **Вход в систему**
    
    Пользователь открывает веб-приложение или мобильное приложение. Если пользователь не авторизован, система предлагает войти или зарегистрироваться. После успешной авторизации пользователь попадает на главный экран. Если сессия уже существует, авторизация восстанавливается автоматически.
    
2. **Главный экран**
    
    Пользователь видит историю своих записей, последние обработанные файлы, папки и кнопку создания нового распознавания. На этом же экране доступны поиск, фильтрация и сортировка записей.
    
3. **Создание нового распознавания**
    
    Пользователь выбирает способ добавления аудио: загрузить существующий файл или, в мобильном приложении, записать аудио непосредственно через микрофон.
    
4. **Выбор файла**
    
    Пользователь выбирает аудио- или поддерживаемый видеофайл с устройства. Система проверяет формат, размер и корректность файла. При ошибке пользователь получает сообщение и может выбрать другой файл.
    
5. **Запись аудио с телефона**
    
    В мобильном приложении пользователь может начать запись через микрофон, поставить её на паузу, продолжить или завершить. После окончания запись можно прослушать, переименовать или удалить перед отправкой.
    
6. **Настройка записи перед отправкой**
    
    Пользователь указывает название записи и при необходимости выбирает папку или добавляет теги. После этого запускает обработку.
    
7. **Загрузка файла на сервер**
    
    Frontend или Mobile отправляет файл в Backend. Пользователь видит прогресс загрузки. При потере соединения система отображает ошибку и позволяет повторить загрузку.
    
8. **Создание задачи обработки**
    
    Backend сохраняет информацию о записи, создаёт задачу обработки и присваивает ей статус, например «В очереди». Файл сохраняется в файловом хранилище, а информация о нём — в базе данных.
    
9. **Передача файла AI/ML-модулю**
    
    Backend передаёт задачу в сервис интеллектуальной обработки. Web и Mobile напрямую с AI/ML-модулем не взаимодействуют.
    
10. **Обработка аудио**
    
    AI/ML-модуль выполняет подготовку аудио, распознавание речи, формирование транскрипции, определение таймкодов и разделение реплик по спикерам. (diarization)
    
11. **Интеллектуальная обработка текста**
    
    После получения транскрипции выполняется исправление ошибок распознавания, восстановление пунктуации, структурирование текста и улучшение его читаемости.
    
12. **Анализ содержимого**
    
    Система формирует краткое содержание записи, ключевые тезисы, основные темы, принятые решения и поставленные задачи.
    
13. **Обновление статуса обработки**
    
    Во время выполнения пользователь видит актуальный статус: «Загружается», «В очереди», «Распознавание речи», «Анализ текста», «Формирование результатов», «Готово» или «Ошибка».
    
14. **Завершение обработки**
    
    AI/ML-сервис возвращает результаты Backend. Backend сохраняет транскрипцию, таймкоды, спикеров, summary и остальные результаты анализа в базе данных.
    
15. **Уведомление пользователя**
    
    После завершения обработки пользователь получает обновление интерфейса. В мобильном приложении дополнительно может прийти push-уведомление о завершении обработки.
    
16. **Просмотр результата**
    
    Пользователь открывает запись и видит её название, дату, длительность, статус и результаты обработки. Доступны исходная транскрипция и исправленная версия текста.
    
17. **Просмотр транскрипции**
    
    Пользователь читает полный текст разговора. Если доступно разделение по спикерам, каждая реплика отображается отдельно с указанием говорящего и временной метки.
    
18. **Работа с аудиоплеером**
    
    Пользователь может воспроизводить запись, ставить её на паузу, перематывать и изменять скорость воспроизведения. По нажатию на таймкод система переходит к соответствующему фрагменту аудио.
    
19. **Просмотр результатов анализа**
    
    Пользователь переключается между разделами: полная транскрипция, краткое содержание, ключевые тезисы, темы, решения и задачи.
    
20. **Редактирование результата**
    
    При необходимости пользователь может изменить название записи, исправить текст транскрипции, изменить папку или теги. Изменения отправляются в Backend и сохраняются.
    
21. **AI-чат по записи**
    
    Пользователь открывает чат и задаёт вопрос по содержимому конкретной записи, например: «Какие сроки обсуждались?» или «Что решили по поводу релиза?». Backend передаёт запрос AI/ML-сервису вместе с контекстом записи и возвращает ответ пользователю. История диалога сохраняется.
    
22. **Экспорт результата**
    
    Пользователь может экспортировать транскрипцию, краткое содержание или полный результат анализа в доступном формате. Backend формирует файл и предоставляет его для скачивания.
    
23. **Sharing на мобильном устройстве**
    
    Пользователь может поделиться готовым результатом через системное меню Android: отправить его в мессенджер, почту, заметки или другое приложение.
    
24. **История распознаваний**
    
    Все предыдущие записи доступны в истории. Пользователь может открыть любую завершённую запись и повторно просмотреть транскрипцию и результаты анализа.
    
25. **Поиск и фильтрация**
    
    Пользователь может искать записи по названию и другим доступным параметрам, фильтровать их по статусу, папке, тегам или дате и менять порядок сортировки.
    
26. **Работа с папками**
    
    Пользователь создаёт папки для организации записей, например «Собеседования», «Совещания», «Учёба». Записи можно перемещать между папками, а папки — переименовывать и удалять.
    
27. **Удаление записи**
    
    Пользователь выбирает удаление записи и подтверждает действие. Backend проверяет права доступа и удаляет либо помечает на удаление запись, связанные результаты и при необходимости исходный файл.
    
28. **Обработка ошибки распознавания**
    
    Если обработка завершилась ошибкой, пользователь видит соответствующий статус и описание ошибки. Он может повторно запустить обработку или удалить запись. Уже сохранённые данные при этом не должны теряться.
    
29. **Потеря интернет-соединения**
    
    При отсутствии сети приложение отображает offline-состояние. Ранее закешированные записи и результаты могут оставаться доступными для просмотра. После восстановления соединения данные синхронизируются с Backend.
    
30. **Профиль и настройки**
    
    Пользователь может открыть профиль, изменить доступные данные аккаунта, управлять настройками уведомлений, темой приложения и выйти из аккаунта.
    
31. **Завершение сессии**
    
    После выхода Backend завершает пользовательскую сессию или отзывает соответствующие токены. Приложение возвращает пользователя на экран авторизации.
    

## end-to-end flow

**Web / Mobile → Авторизация → Главный экран → Загрузка или запись аудио → Backend → Создание задачи → AI/ML-обработка → Backend → Сохранение результата → Уведомление пользователя → Транскрипция и анализ → AI-чат / экспорт / редактирование → История и папки.**
